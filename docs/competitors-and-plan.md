## 3. Причины медленного старта по ссылке (п.6)

Измерено в этой среде с настоящим YouTube (yt-dlp 2026.10.26, Node 24):

- поиск `ytsearch5:` — 2,2 с;
- один вызов извлечения видео (метаданные) — около 3,5 с;
- запуск потока тем же yt-dlp — ещё около 3,5 с (повторный разбор той же страницы).

Из этой среды полное извлечение видео блокируется проверкой «подтвердите, что вы не бот» (IP центра обработки данных), поэтому полный запуск трека измерить не удалось. Цифры 3,5 с получены по времени до ответа и совпадают между вызовами, но на вашем компьютере они могут отличаться.

Причина задержки: `/play <ссылка>` делал **два последовательных запуска** yt-dlp, и каждый заново разбирал страницу.

Решения:

1. **Один процесс вместо двух.** Поток запускается сразу при разборе ссылки, метаданные приходят строкой JSON в stderr (проверено: при `-o -` и `--no-simulate` yt-dlp пишет `--print` в stderr, а звук в stdout). Запущенный процесс ждёт в «прогретом» состоянии до 45 с и передаётся плееру. Ожидаемый выигрыш — одна из двух задержек.
2. **Выбор из поиска не делает лишних запросов:** метаданные уже есть в результатах поиска, остаётся один запуск потока.
3. **Мгновенная обратная связь:** сразу после выбора пользователь видит «⏳ Загружаю…», а панель в канале показывает «Загружается».
4. Кэш результатов поиска на 5 минут: повторный запрос мгновенный.

## 4. План реализации

Порядок и критерий готовности каждого шага (всё с тестами):

1. **Поиск YouTube** (`/play текст`): провайдер `search()`, хранилище ожидающих выборов, выбор кнопками 1–5, отмена, срок жизни 2 минуты, выбор только тем, кто искал.
2. **Один процесс yt-dlp** для ссылки (быстрый старт) + обратная связь «Загружаю».
3. **Панель после `/play`** в том канале, где вызвали, с кнопками как на скриншоте; при новом треке панель переносится вниз чата.
4. **Объявления о действиях**: пауза, продолжение, пропуск, стоп, громкость, повтор, перемешивание, очистка, удаление, перемещение, подключение и отключение, потеря соединения, бездействие, ошибки треков, конец очереди. Режим `/settings announce`: все / важные / выкл.
5. **Свои файлы**: вложение в `/play`, проверка расширения, размера и содержимого (ffprobe), сохранение в `music/uploads`, мгновенное добавление в каталог.
6. **Из анализа ботов**: Prev, Shuffle, Vol±, Favorite, `/favorites`, `/play … next`, `/skipto`, режим 24/7, автоплей.
7. **Хвосты установщика**: `update.cmd` для установки из ZIP, честные формулировки в README и `docs/deployment.md`, тест без обращения к реальному Discord.
8. Проверка (`npm run check`), документация, коммит и push в ветку `claude/quirky-brahmagupta-lz9mjn`.

## 5. Что сделано в итоге

Версия 1.1.0, 2026-11-07. Пункты плана 1–8 выполнены. Отличия от плана:

- **Автоплей** не сделан: список «похожих» видео YouTube (`RD…`) из среды разработки недоступен («playlist type is unviewable»), а разбор страницы видео блокируется проверкой «не бот», поэтому проверить реализацию было бы нечем.
- **Seek**, **фильтры**, **тексты песен**, **Spotify**: не делались по причинам из таблицы выше.
- Ускорение: сделан один запуск yt-dlp вместо двух; измеренное время разбора страницы — около 3,5 с, поиска — 2,2 с.

## 6. Ограничения, которые остаются

- Ничего из YouTube-части нельзя проверить на реальном воспроизведении в этой среде; проверено на поддельном yt-dlp и на реальном поиске.
- Работа в голосовом канале Discord не проверялась ни в этой, ни в предыдущей сессии.
